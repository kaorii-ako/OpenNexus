# Vault writing convention

Every note written to `vault/` follows this shape, whether it came from domain
work or from the orchestrator recording one of its own edits. Implemented in
`backend/orchestrator/vault.py`.

## Frontmatter

```yaml
---
date: 2026-07-27          # YYYY-MM-DD, UTC
domain: dev               # dev | trading | orchestrator
tags: [tag-one, tag-two]  # inline list
links: [other-note-slug]  # outbound edges, by note slug (filename without .md)
---
```

`links:` is the authoritative edge source for the HUD graph. Inline
`[[wikilinks]]` in the body are also collected, so a note written by hand in
Obsidian still appears in the graph.

Self-edit notes add:

```yaml
kind: self-edit
proposal: prop_1a2b3c4d
pattern: missing_trigger
target: skills/dev/SKILL.md
```

## Body

Start with a single `# H1`. That line becomes the node title in the HUD graph;
without it the filename is used.

## Layout

```
vault/
├── README.md          # documents this convention for humans
├── evolution/         # orchestrator self-edits — written by `nexus evolve`
├── dev/               # dev domain work
└── trading/           # trading domain work
```

## Pre-edit content blocks

Self-edit notes embed the complete pre-edit file content between markers:

```
<!-- nexus:pre-edit-content:start -->
````````markdown
...original file, byte for byte...
````````
<!-- nexus:pre-edit-content:end -->
```

An eight-backtick fence is used so that any fence inside the captured file
cannot terminate the block early. `nexus evolve --revert` reads exactly this
block, which is why a self-edit note is a record of the change *and* the means
to undo it — never a summary.

## What is never written here

Only two kinds of note are generated by code: domain work, and orchestrator
self-edits. Nothing else. If a note would have no real source behind it, it does
not get written.
